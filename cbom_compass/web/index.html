What the bands mean

Urgency is the priority score, which is not the same as the Mosca test alone.

# timing modulates a need to migrate — # it never creates one exposure_gap = (X + Y) − Z_years urgency = clamp(gap / SCALE, 0, 1) compliance = nearness of the NIST deadline vulnerability = 1.0 broken · 0.8 deprecated 0.3 policy-only · 0.0 adequate timing = max(urgency, compliance, FLOOR) risk = vulnerability × timing × (0.6 + 0.4 × hndl) score = risk × criticality_weight
Why multiply rather than take a max? Scanning paramiko, an earlier version scored its already-migrated ML-KEM key exchange at 0.60 — purely because SSH session keys protect long-lived access. Nothing needed migrating, so no timeline should have made it urgent. Vulnerability now gates everything: adequate algorithms score zero whatever their data lifetime.
Why the floor? 3DES protecting session data is still worth replacing, so timing never drops to zero and weak cryptography always registers.
